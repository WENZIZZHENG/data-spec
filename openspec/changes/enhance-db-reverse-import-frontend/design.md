## Context

`ReverseImport.vue` 目前已经支持 SQL DDL 和数据库直连两种模式。数据库直连模式能填写连接信息、测试连接、加载表、选择表、生成预览并确认导入，但这些动作分散在同一块表单里，用户很难判断当前进度、下一步和导入前风险。

本次只优化个人/小团队自用场景的前端主流程。后端已有 API 覆盖连接测试、表列表、metadata 预览和候选字段导入，因此实现应优先复用现有接口和类型。

## Goals / Non-Goals

**Goals:**

- 用步骤条呈现数据库直连导入流程，明确当前阶段和下一步动作。
- 让表选择更适合真实库：搜索、全选、清空、已选统计。
- 让预览结果更可控：按表展示候选字段，并允许用户勾选本次导入的字段。
- 导入前给出确认信息，导入后提供结果摘要和跳转字段库动作。
- 保持页面可构建、可类型检查，并遵循现有 Vue 3 + Element Plus 风格。

**Non-Goals:**

- 不保存数据库密码或连接配置。
- 不新增定时同步、后台任务或自动对比历史版本。
- 不修改源数据库。
- 不引入审批流、权限流或企业治理流程。

## Decisions

1. **单页步骤化，而不是新增路由或向导组件**
   - 理由：反向导入仍是一个页面内的短流程，新增路由会增加状态传递和返回处理复杂度。
   - 替代方案：拆成多个页面；缺点是个人使用时切换成本更高。

2. **候选字段选择只在前端维护，不改变后端预览契约**
   - 理由：已有 `fieldCandidates` 足以完成手动确认导入，前端可以用 `tableName.columnName` 作为稳定选择键。
   - 替代方案：后端返回候选 ID；当前没有必要，会扩大接口和测试范围。

3. **导入状态以摘要和列表呈现，不保存导入历史**
   - 理由：P4-12 聚焦“本次操作完成感”，长期历史可后续与操作记录体系合并。
   - 替代方案：新增导入记录；会牵涉持久化和查询页面，超出边界。

4. **视觉采用工作台式布局**
   - 理由：这是高频维护工具，页面应安静、清晰、可扫描。设计锚点是顶部步骤条和预览区的表分组，不做营销式 hero 或装饰背景。

## Risks / Trade-offs

- **预览候选字段没有后端唯一 ID** → 使用 `tableName.columnName` 作为前端选择键；同一库同一表字段天然唯一，满足当前导入粒度。
- **后端无法区分冲突详情** → 第一版只展示导入结果里的新增/跳过列表；如后端未来返回冲突原因，再补充细分状态。
- **页面状态较多** → 通过小型 computed 和重置函数收敛状态，避免引入全局 store。
- **真实数据库验证依赖外部环境** → 自动验证以 `pnpm build` 为准，手动验收记录连接、选表、预览、导入流程。
