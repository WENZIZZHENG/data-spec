## Context

反向导入页当前已经支持数据库直连、表加载、候选预览、差异比对和确认导入；字段库页已经支持字段 CRUD 和来源查看。高频使用中的问题主要是页面状态没有延续：切换页面或刷新后，非敏感连接信息、表选择、搜索词和差异筛选会丢失；确认导入后跳到字段库也无法自动定位刚导入的字段。

前端设计方向延续现有 Element Plus 管理台风格：低干扰、偏工具型、密度适中，不做视觉大改版，只增加可感知的状态保留和跳转联动。

## Goals / Non-Goals

**Goals:**

- 以项目为维度保存反向导入页的非敏感流程状态。
- 明确剔除数据库密码、token、完整连接串等敏感信息。
- 字段库支持 URL query 过滤关键词，反向导入完成后可带关键词跳转。
- 使用纯函数承载可测试逻辑，接入现有 `pnpm test`。

**Non-Goals:**

- 不新增后端 API、数据库表或服务端连接预设。
- 不保存数据库密码，不保存完整 JDBC URL。
- 不做复杂状态管理库改造，不引入新前端依赖。
- 不实现 P6-10 的多预设管理和无密复用模型。

## Decisions

1. 使用 `localStorage` 保存第一版本地记忆。
   - 原因：P5-8 是前端细节打磨，不应提前引入后端持久化模型。
   - 替代方案：后端连接预设。该方案更完整，但属于 P6-10，涉及数据模型和安全边界。

2. 新增 `reverseImportMemory` utility 封装读写、清洗和跳转 query。
   - 原因：SFC 中直接读写 localStorage 很难单测，也容易遗漏敏感字段。
   - 替代方案：直接在 `ReverseImport.vue` watch 中拼对象。实现更快，但回归风险更高。

3. 字段库只做前端页内过滤，不改 `pageFields` API。
   - 原因：当前字段数量和 P5-8 范围更适合前端局部过滤；后续 P6-19 会做标准字段检索 API。
   - 替代方案：扩展后端分页查询。会改变 API 契约，不符合本轮最小改动。

4. 记忆恢复时不恢复密码，也不自动发起连接请求。
   - 原因：避免让用户误以为 DataSpec 保存了凭据，同时防止刷新页面后自动触达数据库。

## Risks / Trade-offs

- 本地缓存损坏或结构过期 → 读取失败时返回空状态，并允许页面继续使用默认值。
- 前端页内过滤只过滤当前分页 → 在字段很多时可能找不到非当前页字段；P6-19 会用后端检索补齐。
- localStorage 是浏览器本地能力 → 不跨设备同步，也不适合作为团队共享预设；P6-10 另行处理。
