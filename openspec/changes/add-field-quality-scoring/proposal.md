## Why

字段标准越多，越需要判断哪些字段对 AI 仍然“信息不足”：缺少注释、别名、示例值、敏感标记、枚举关联或状态说明时，AI 会拿到看似完整但语义不够可靠的字段目录。P6-5 要提供一个只读的质量评分入口，帮助个人/小团队优先修补低质量标准字段。

## What Changes

- 新增字段质量评分 API，按项目扫描标准字段，输出项目级 summary、字段级 score、等级、问题列表和修复建议。
- 质量检查覆盖缺注释、缺别名、缺示例值、疑似敏感未标记、枚举/状态类字段未关联代码集、废弃/禁用字段仍缺少替代说明等高价值问题。
- 前端新增字段质量视图，支持按等级/问题筛选、按分数排序，并能跳转到字段库编辑具体字段。
- 质量结果保持只读，不自动修改字段标准，不调用外部 LLM。
- README/TODO 更新 P6-5 状态、能力说明和边界。

## Capabilities

### New Capabilities

- `field-quality-scoring`: 项目级标准字段质量评分、低质量字段定位和修复建议。

### Modified Capabilities

无。

## Impact

- 后端：新增字段质量模型、服务和 `/api/fields/quality` 查询接口，复用现有 `FieldService` 字段列表。
- 前端：新增质量报告 API wrapper、类型、路由/导航和页面，复用当前项目 store 与 Element Plus。
- 测试：新增后端质量评分单测，前端新增展示/工具函数测试或最小页面构建验证。
- 文档：更新 README、TODO 和 OpenSpec tasks。
- 边界：不新增数据库表，不自动修复字段，不引入复杂质量 KPI 或外部 LLM。
