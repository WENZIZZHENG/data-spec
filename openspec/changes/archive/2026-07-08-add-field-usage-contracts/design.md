## Context

DataSpec 已经有字段生命周期、敏感标记、格式约束、使用示例、字段检索、标准问答、字段推荐、AI Context 和 DDL/Prompt 工作流。P6-187 的缺口不是再解释字段含义，而是把字段在真实 SQL/DDL 中“该怎么用、不该怎么用”变成稳定契约。

本变更是 SDD full：它会新增字段级持久化属性、迁移脚本、OpenAPI 可见字段、前端编辑入口和 AI Context 输出契约。所有新增字段必须兼容旧数据，默认空契约不改变现有字段行为。

## Goals / Non-Goals

**Goals:**
- 字段可保存推荐使用场景、禁用场景、join、默认过滤、聚合、替代指导和常见误用。
- 字段详情、检索、标准问答和 AI Context 能读取这些契约，并在证据不足或禁用场景中提示人工确认。
- DDL/Prompt 上下文能提醒 AI 避免把展示字段、内部状态、废弃字段或统计专用字段用于错误场景。
- 迁移、API、前端类型、测试和 OpenSpec 验证都能覆盖新增公共表面。

**Non-Goals:**
- 不建设完整指标平台、血缘平台、审批流或字段使用统计系统。
- 不要求历史字段一次性补齐契约。
- 不自动重写 SQL，不根据契约直接执行数据库写入。
- 不把业务数据行、凭据、完整 JDBC URL、DSN 或 Authorization 写入契约。

## Decisions

1. **使用 Field 兼容列承载第一版契约，而不是新建重型子表。**
   - 方案：在 `ds_field` 增加 `preferred_use_cases`、`avoid_when`、`join_hints`、`default_filters`、`aggregation_hints`、`replacement_guidance`、`misuse_examples` 等可空字段。
   - 原因：第一版更像字段元数据的一部分，读写路径已经围绕 Field API、字段库、快照和 AI Context 展开；可空列最小影响现有查询和前端表单。
   - 备选：新建 `ds_field_usage_contract` 表。它更适合复杂版本化和多条规则，但会增加 CRUD、排序、权限和事务边界，不符合第一版轻量目标。

2. **契约字段先用文本或分隔文本语义，AI Context 再输出结构化数组。**
   - 方案：后端保存简洁文本，导出时按换行、逗号或项目已有 split 规则转成数组摘要。
   - 原因：个人/小团队可以快速填写；AI Context 仍获得结构化、可机器读取的 `usageContract` 对象。
   - 备选：强制 JSON schema 输入。它更严格，但前端填写成本高，也容易让轻量字段维护变慢。

3. **使用契约不替代 Standard Usage Examples。**
   - 方案：usage contract 表达字段级稳定边界，usage examples 继续表达场景样例和反例。
   - 原因：契约适合短约束，示例适合长输入/输出和 SQL 片段；混在一起会让 AI Context 噪声变高。

4. **搜索和问答只做提示与降级，不做自动裁决。**
   - 方案：字段检索和标准问答返回使用契约摘要、禁用提示和 nextActions；如果问题命中 `avoidWhen`、废弃/停用/草稿字段或缺契约证据，则进入需要确认状态。
   - 原因：契约本身是人维护的标准证据，不应让 AI 在证据不足时伪装成确定结论。

## Risks / Trade-offs

- [Risk] 文本字段过自由，AI 可能难以稳定解析。→ AI Context 输出时统一成数组字段，并在 schema 中描述字段含义。
- [Risk] Field 表继续变宽。→ 第一版只增加高价值字段；后续如果出现多版本、多条规则和审批需要，再迁移到子表。
- [Risk] 用户把凭据或真实业务数据写入契约。→ 保存和导出路径复用已有敏感信息检测；测试覆盖拒绝明显 secret-like 内容。
- [Risk] 历史快照和备份恢复遗漏新字段。→ 实施任务明确覆盖快照、备份或复用包相关字段传播检查。
- [Risk] DDL/Prompt 消费契约后仍可能误用。→ 第一版仅提供证据和警告，不承诺自动正确生成。

## Migration Plan

1. 新增可空列和字段说明，不回填历史数据。
2. 后端 entity/request/response 和 OpenAPI 以可选字段暴露，旧调用方无需传参。
3. 前端字段库在现有编辑表单中新增可折叠的“使用契约”区域，空值不展示噪声。
4. AI Context 和搜索输出以 additive 字段扩展，保持既有字段目录和搜索结果兼容。
5. 回滚时可隐藏前端入口并停止读取新增字段；数据库可保留可空列，避免破坏已写入标准。

## Open Questions

- 第一版是否把字段使用契约纳入标准快照、备份恢复、复用包和标准变更预览的完整传播范围。默认倾向纳入快照和 AI Context，备份/复用按现有 Field 字段复制路径最小补齐。
