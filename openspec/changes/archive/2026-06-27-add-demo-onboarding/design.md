## Context

当前项目创建已支持导入内置标准字段和数据域，但演示闭环还缺少模板、显式规则配置和入口引导。前端已有工作台、项目列表、DDL 生成、SQL 校验、AI 规则导出和反向导入页面，因此 P4-10 应复用已有页面，不引入新的 onboarding 路由或复杂状态。

## Goals / Non-Goals

**Goals:**
- 一键创建或复用演示项目，保证重复点击不会产生同名项目错误。
- 演示项目包含能驱动 DDL 生成和 SQL 校验的最小数据：内置字段/数据域、订单表模板、核心规则配置、示例 SQL。
- 前端在无项目和项目列表场景提供清晰入口，并在创建后自动切换当前项目。
- 通过路由参数复用现有 SQL 校验和 DDL 生成页面的演示输入。

**Non-Goals:**
- 不新增数据库迁移、用户行为追踪、复杂引导状态或多步骤向导页面。
- 不保存数据库密码，不修改反向导入后端契约。
- 不实现企业版教程、审批流、发布流或角色矩阵。

## Decisions

1. **后端提供 `POST /api/projects/demo`，而不是前端串多个 CRUD。**
   - 理由：演示项目包含项目、字段、规则和模板，后端事务能保证种子数据一致。
   - 替代方案：前端依次调用项目、规则、模板 API；失败恢复复杂，也会把种子规则暴露到页面逻辑。

2. **演示项目按名称幂等复用。**
   - 理由：个人工具里用户可能多次点击“创建演示项目”，复用同名项目更符合预期。
   - 替代方案：每次追加序号创建新项目；容易污染项目列表。

3. **演示模板直接使用内置标准字段生成模板字段。**
   - 理由：能马上驱动 DDL 生成和数据字典导出，不需要新增模板导入格式。
   - 替代方案：新增模板 YAML 资源；当前只需一个演示模板，代码内种子更小。

4. **前端快速开始使用已有路由和 query 参数。**
   - 理由：现有页面已经完成核心能力，query 参数只负责预填演示输入，避免新增页面和状态同步。

## Risks / Trade-offs

- **演示种子代码和内置 YAML 可能分散** → 演示服务只保存模板/规则种子，字段仍由现有 `BuiltInStandardsImportService` 导入。
- **重复点击可能补种已有项目资产** → 模板字段和规则按名称/编码去重，保持幂等。
- **安全模式下普通项目 token 不能创建项目** → 沿用 P4-9 的全项目 token 约束；无安全模式下保持开箱可用。

## Migration Plan

无需数据库迁移。发布后新 API 可直接使用；回滚时移除前端入口和后端 demo 服务即可，不影响已有项目数据。
