## 背景

P2-6 需要在不引入审核、发布和权限流程的前提下，让字段标准、代码集和命名规则的变更可追溯。当前主表只有 `created_at/updated_at`，无法回答“谁改了什么字段值、改前改后是什么”。

## 变更

- 新增 `ds_standard_change_log` 表，记录项目、目标类型、目标 ID、动作、before/after JSON 和变更时间。
- 新增轻量日志服务与查询 API。
- 在标准字段、代码集、代码值和规则配置的 create/update/delete/toggle 路径自动记录变更。
- before/after JSON 直接使用当前实体快照，保持个人版可读、可查、低维护。

## 非目标

- 不做审批流、发布版本、权限和操作人体系。
- 不做前端复杂 diff 页面。
- 不追溯历史数据，只记录功能上线后的新变更。
