## Context

字段模型已有 `name`、`displayName`、`aliases`、`category`、`tags`、`dataType`、`codeSetId`、`sensitive`、`status` 等可用于检测冲突的元数据。字段推荐已内置常见语义组，但当前只服务单次推荐，不能给用户一份项目级“哪里重复/哪里冲突”的维护清单。

## Goals / Non-Goals

**Goals:**
- 只读实时检测项目内字段冲突。
- 区分可合并的疑似重复与需要保留但要补说明的语义相近字段。
- 输出结构化结果，前端和后续 CLI/MCP/AI Context 可直接消费。
- 让用户能从报告跳转字段库编辑具体字段。

**Non-Goals:**
- 不自动合并字段，不自动删除历史字段。
- 不做跨项目治理或组织级标准统一。
- 不引入外部 LLM 或向量检索。
- 不保存每次检测结果。

## Detection Rules

- **字段名重复/冲突：** 正常业务创建已阻止同名字段，但检测仍保留兜底规则，覆盖导入或历史脏数据。
- **别名占用：** 某字段别名等于另一个字段名，或同一别名属于多个字段。
- **显示名重复：** 显示名相同或紧密相近时提示疑似重复。
- **语义词组重复：** `user_id/uid/account_id`、`mobile/phone/tel`、`amount/fee/price` 等已知语义组内出现多个标准字段时提示。
- **属性不一致：** 同一冲突组内数据类型、代码集、敏感标记或状态不一致时升级严重级别。

## Decisions

- **第一版使用确定性规则。** 复用字段名、别名、显示名和内置语义词，不引入 embedding。
- **输出 group 级结果。** 每个冲突组包含多个字段和 evidence，前端按组展示比逐字段更清楚。
- **实时计算。** 字段量在个人/小团队场景可接受，后续大数据量性能基线再决定是否缓存。

## Risks / Trade-offs

- **[Risk] 语义组可能误报。** → 结果区分 `DUPLICATE` 与 `RELATED`，并给出“确认是否合并/补充说明”的建议，不自动修改。
- **[Risk] 别名解析格式不一致。** → 第一版按逗号分隔并 trim/dedup，和 AI Context 导出保持一致。
- **[Risk] 与字段质量页有重叠。** → 字段质量关注单字段完善度，字段冲突关注多字段之间的关系，前端独立页面展示。

## Migration Plan

新增 API 和页面不影响现有字段 CRUD。回滚时删除新增 `fieldconflict` 包、前端页面/API/types/test 和文档即可。
