# MyBatis 性能规则

本文件只在涉及查询、分页、批量写入、导入导出、列表接口或性能评审时读取。性能优化必须先保证语义、权限和数据一致性正确。

## 查询风险

- N+1 查询：不要在循环中按 id 单条查询。优先一次性批量查询、`foreach`、JOIN 或预聚合，再在内存中按 key 组装。
- 全量拉取：大表列表接口不得无 `LIMIT` / 无分页直接 `selectList`；导出任务也要分批读取、设置上限或走异步任务。
- 嵌套 `resultMap`：一对多嵌套可能放大结果集或产生笛卡尔积，复杂聚合优先拆成主表分页 + 子表批量查询。
- 动态排序：排序字段、方向必须 allowlist；排序字段要和索引策略一起检查。

## 写入与索引

- 批量写入优先使用批量 insert/update 能力，如项目已有的 batch mapper、MyBatis Plus 扩展方法或 JDBC batch；避免循环单条 insert 造成大量 round trip。
- WHERE 条件字段、排序字段、外键字段、唯一性校验字段要检查索引；多条件查询关注组合索引顺序。
- 分页查询必须有稳定排序；深分页或宽表查询要考虑基于游标、seek pagination 或覆盖索引。
- 性能优化不得绕开 repository port、权限归属、逻辑删除、租户/项目隔离和脱敏规则；相关分层边界见 `layering.md`，安全与脱敏见 `quality-security.md`。
